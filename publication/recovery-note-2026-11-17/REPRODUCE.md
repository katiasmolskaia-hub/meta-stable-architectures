# Как проверить материал и попробовать пример

## Прочитать без установки

Основной текст: [note.ru.md](note.ru.md). В его источниках указаны три отчёта со ссылками на протоколы и сохранённые данные. Для чтения результатов расчёты не нужны.

Исходная открытая ревизия: `a4c8880e469445cb203ee157d52990b2e9b6d5bc` репозитория [meta-stable-architectures](https://github.com/katiasmolskaia-hub/meta-stable-architectures/tree/a4c8880e469445cb203ee157d52990b2e9b6d5bc). Названная ревизия закрепляет научные серии. Текст заметки, аудит и оформление добавлены позднее в выпуск `recovery-note-v1.0.1`; они не приписываются старому коммиту.

## Проверить происхождение чисел

Из корня проекта:

```sh
python publication/recovery-note-2026-11-17/audit_note.py
```

Скрипт читает архив, пересчитывает средние ключевых групп и парные разности из `runs.csv`, сопоставляет их со сводками и сохраняет только локальный `evidence.json` рядом с заметкой. Он также сверяет участвующие архивные файлы с манифестом. Интервалы берутся из `paired_comparisons.csv`, а не оцениваются заново. Это аудит сборки заметки, не новый эксперимент.

## Один короткий пример

Для него достаточно NumPy. Версии, записанные при исходных опытах: Python 3.12.14 и NumPy 2.3.5. Для изолированной установки можно создать обычное виртуальное окружение; не заменяйте зависимости других проектов.

```sh
python -m pip install numpy==2.3.5
python publication/recovery-note-2026-11-17/quick_demo.py
```

Пример сравнивает три правила на одном заранее выбранном исходном мире `seed=21000`: автономные потоки, запрос при устойчивой нехватке, запрос по двум признакам. Это первый диагностический seed исходной серии, а не подобранная удачная реализация. Все три строки сверяются с архивными результатами с допуском `1e-10`; архив и `outputs/` не изменяются. Один такой запуск не устанавливает среднюю пользу метода.

Другой мир: `python publication/recovery-note-2026-11-17/quick_demo.py --seed 21001`. Для нового seed вне исходного диапазона сопоставление с архивом недоступно. На другом численном окружении дискретные решения могут расходиться; не ослабляйте проверку только ради получения отметки совпадения.

## Повторить полные серии

Полные команды из корня репозитория; каталоги выбраны новыми, чтобы сохранить архив. Эти расчёты существенно больше короткого примера.

```sh
python simulations/experiment_minimal_observer.py --workers 4 --out outputs/note_observer_reproduction
python simulations/report_minimal_observer.py --out outputs/note_observer_reproduction
python simulations/experiment_help_timing.py --workers 4 --out outputs/note_timing_reproduction
python simulations/report_help_timing.py --out outputs/note_timing_reproduction
python simulations/experiment_repeated_help.py --workers 4 --out outputs/note_repeated_reproduction
python simulations/report_repeated_help.py --out outputs/note_repeated_reproduction
```

Используйте рабочие модули, соответствующие закреплённой ревизии и снимкам, а не запускайте отдельный снимок вне его зависимостей. При занятых каталогах выберите новые имена. Команда проверок: `python -m unittest discover -s simulations -p 'test_*.py'`. В отдельном пакете она запускает 12 включённых проверок этих трёх серий; все 12 прошли при изолированной проверке пакета. Полный исторический набор всех направлений проекта в пакет не включён и заново не запускался. Точный журнал проверок находится в `VALIDATION.json` в корне пакета.

## Пересобрать PDF

Сборка требует ReportLab, Pillow и Arial с кириллицей. Скрипт `build_pdf.py` читает тот же `note.ru.md`; отдельной вручную расходящейся версии текста нет. Готовый PDF сохраняется в `output/pdf/local-recovery-note-ru.pdf`. График в нём взят из архивной серии без изменения данных.
